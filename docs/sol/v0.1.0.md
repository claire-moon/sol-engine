# SOL Engine v0.1.0

Status: release

## Objective

Run the first complete E1M1 graybox produced by `sol-editor` while keeping core UZDoom behavior and classic Doom episode progression intact, with the fixed SOL presentation/gameplay stack loaded deterministically on every supported launch.

## Included

- Engine/editor compatibility metadata for `0.1.0`.
- E1M1 MAPINFO identity and normal progression to E1M2.
- Explicit Episode 1 cluster, level number, title patch, secret-exit target, and par time.
- Classic level-complete statistics and Episode 1 "you are here" intermission map.
- Updated runtime bootstrap message and shared SOL application icon.
- Canonical `sol/mods/stack.json` contract for eight mandatory user-supplied mods.
- Deterministic stack resolution through `tools/sol-stack.sh` with fail-closed missing-file checks.
- Strict `tools/sol-run.sh` selection of the locally built SOL engine with no generic system-UZDoom fallback.
- CI validation for package contents, metadata, branding, classic progression, exact mod order, and missing-mod rejection.

## Mandatory stack

Load order is part of the v0.1.0 compatibility contract:

1. `PSSFX.zip`
2. `flashlight_plus_plus_v9_1.7z` staged as `flashlight_plus_plus_v9_1.pk3`
3. `FinalCustomDoom-v1.0.0-beta.pk3`
4. `jdra-Angled-Doom-Lite-1.2.1.pk3`
5. `TrooCullers2.5.pk3`
6. `TiltPlusPlus.pk3`
7. `Universal-Weapon-Sway-master.zip`
8. `nashgore_next.zip`

The source archives are not distributed by SOL. `sol-editor` is responsible for staging the user-supplied files into the local sibling `vend` tree and recording checksums.

## Acceptance checks

1. `tools/sol-package.sh` produces `sol-v0.1.0.pk3`.
2. The runtime PK3 contains MAPINFO, ZSCRIPT, and the SOL bootstrap class.
3. `sol/mods/stack.json` contains the exact eight-entry v0.1.0 order.
4. `tools/sol-stack.sh` rejects a launch when any mandatory runtime file is absent.
5. `tools/sol-run.sh` selects only the configured or locally built `sol-engine` executable.
6. The editor graybox package loads after the runtime package and mandatory stack.
7. E1M1 starts as “Hangar: Arrival” and exits normally toward E1M2.
8. The Doom statistics screen and Episode 1 world map appear after completion.
9. MAPINFO does not use `nointermission` or any seamless-transition behavior.
10. Existing UZDoom compilation workflows remain green.
11. A local full-stack playthrough records no ZScript, MAPINFO, or mod-load errors.

For v0.1.0, the supported launch contract is enforced by SOL tooling. Direct raw `uzdoom` invocation is intentionally outside this release contract; binary-level stack embedding is scheduled for standalone-product hardening.
