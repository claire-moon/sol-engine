# SOL Engine v0.3.0 — identity and native boot

v0.3.0 is the first release in the engine-first roadmap. It turns the inherited
runtime into a separately identified SOL executable while preserving the
existing gameplay, bundle, wadpack, map, and story contracts.

## Product identity

- Executable: `sol-engine` / `sol-engine.exe`
- Engine support archive: `sol-engine.pk3`
- Application name: `SOL Engine`
- Application ID: `io.github.claire_moon.solengine`
- Save signature: `SOLENGINE`
- Mandatory gameplay bundle: `sol.pk3`

Windows resources, macOS bundle metadata/icons, Linux desktop/AppStream data,
documentation packaging, crash metadata, artifact names, and release names use
the SOL identity. The inherited binary updater is disabled.

Configuration, save, data, cache, screenshot, log, and portable-profile paths
derive from the SOL product constants. A fresh install therefore creates SOL
state and does not adopt UZDoom state.

## Native boot contract

The executable discovers a registered Doom or Ultimate Doom IWAD, or opens a
SOL-branded native picker when none is found. It rejects Doom shareware, Doom II
family games, and unrelated IWADs.

After engine support and the IWAD, the executable requires adjacent `sol.pk3`.
It parses `SOLPACK.json`, requires embedded `THIRD_PARTY.md`, and verifies schema
1, bundle contract 1, wadpack contract 2, 18 wadpack entries, and 20 logical
components. Only then is the bundle mounted. Optional command-line/autoload
resources retain later override precedence.

No player-facing or editor launcher supplies `-file sol.pk3` in this contract.

## Modified-run contract

Run integrity has a deterministic native reason mask. Extra files/autoloads,
DeHackEd/BEX patches, startup warps, cheats, console travel, multiplayer, and
developer overrides set read-only diagnostics and disable persistent campaign
progression writes. The reason mask survives save/load, and `sol_run_status`
prints the current state.

Future progression systems must use the centralized native write guard. v0.3.0
adds the boundary before v0.6.0 introduces chapter persistence, so no legacy
unguarded campaign data exists.

## Compatibility carried forward

- Bundle contract 1 and `sol.pk3`
- Wadpack contract 2 with 18 entries
- Story contract 1 with IDs 1–65535
- Classic E1M1 map/progression behavior
- Native numbered embedded-archive mounting
- OpenGL/Vulkan upstream runtime foundations

Narrative content and editor UX are intentionally parked. The next phase moves
bundle/resource authority and canonical defaults into this repository.
