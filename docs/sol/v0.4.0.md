# SOL! Engine v0.4.0 — bundle authority, defaults, and geometry foundation

v0.4.0 moves the canonical local gameplay bundle contract into `sol-engine`.
It preserves the completed v0.3 native SOL! identity/boot model while making
resource locking, slot semantics, provenance, final bundle construction, and
canonical configuration engine-owned.

## Engine-owned bundle authority

The engine repository now owns:

- `sol/wadpack.json` schema 2;
- `tools/sol-wadpack.py` importer/locker;
- `tools/sol-wadpack-setup.sh` local setup entry point;
- `tools/sol-bundle.py` bundle contract 2 builder/verifier/materializer;
- `tools/sol-bundle.sh` final local bundle workflow;
- the canonical `THIRD_PARTY.md` inventory.

The sibling editor produces the current content component but delegates final
resource locking and bundle construction to the engine.

## Wadpack contract 3

Twenty logical wadpack slots are defined. Slots 1–10 and 12–19 are active. Slot
11 is retired and slot 20 is reserved. The active count remains eighteen.

HQ PlayStation music is retired/unmounted at slot 11. PreciseCrosshair v1.5.0
uses slot 19. Slot 20 remains deliberately empty. Runtime and content occupy
slots 21 and 22.

Retired/reserved positions are present in metadata only; no dummy archive is
created and those positions are never mounted.

## Bundle contract 2

`SOLPACK.json` schema 2 records the full logical slot table separately from the
physical component table. Active carriers use their real two-digit slot prefix,
so gaps remain visible while lexical archive order still defines native mount
order.

The native engine validates the complete v0.4 contract before mounting
`sol.pk3`, including slot state, ID, runtime name, carrier name, SHA-256,
attribution hash, and the absence of retired/reserved carriers.

## SOLDEFAULTS contract 1

`SOLDEFAULTS.json` is packaged in the SOL!-owned runtime component. It contains
only approved renderer, mod, audio, HUD, and gameplay defaults. Personal paths,
recent-file history, bindings, saves, and player identity are explicitly outside
the contract.

Fresh/default profiles receive the canonical values after ordinary engine CVar
defaults are established. `sol_reset_defaults` reapplies the SOL! values on
demand.

## Procedural North Star startup

The generic startup/loading screen no longer reads a bitmap logo and no longer
draws a progress bar. A deterministic blue-white particle field is rendered
directly by the engine. Startup progress drives those particles from a dispersed
field into the SOL! North Star, so the formation itself communicates loading
progress.

`branding/sol/sol-northstar.svg` is a separate clean identity source: a single
white North Star on transparency. The loading screen does not render that SVG;
the star is generated procedurally.

## Geometry contract 1

v0.4 establishes linked line portals as the first stable SOL! impossible-space
primitive. Reciprocal `Line_SetPortal` pairs can join physically remote spaces
while preserving continuous rendering and player traversal. The contract is
documented in `docs/sol/non-euclidean.md` and is intended as the foundation for
later recursive, topology-changing, and forced-perspective spaces.

The deterministic E1M1 regression map is presented as `TESTMAP`. It contains a
reciprocal linked-portal pair whose visible adjacency does not match the editor's
physical map layout. TESTMAP contains no monsters so portal behavior, lighting,
materials, ReLite, Universal Ambience, props, weapons, and renderer behavior can
be inspected without combat obscuring the geometry test.

## Preserved v0.3 behavior

- native `sol-engine` executable and support archive identity;
- separate SOL! profile/config/save/cache namespaces;
- registered Doom/Ultimate Doom IWAD requirement;
- native adjacent `sol.pk3` discovery;
- modified-run reason mask and progression-write suppression;
- story contract 1 and parked narrative content.

## Distribution boundary

The complete `sol.pk3` remains local-only. Removing HQ PlayStation music does
not clear unrelated third-party resources. PlayStation sound effects remain a
local placeholder, and PreciseCrosshair/libeye plus all other resource assets
remain subject to the recorded resource-level license audit.
